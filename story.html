A+B — 방송상품가 + 배송비 = 결제금액 (기본 입출력)
💡 값을 합치는 가장 기본 연산. 계산의 최소 단위.
🎯 왜 이걸 쓰나: 모든 결제·정산의 출발점 — 안 쓸 수가 없음.

int sum = a + b;

2609
GCD와 LCM — 방송 할인율 약분 표시 · GS&POINT 적립+쿠폰이 다시 겹치는 날 (유클리드·주기)
💡 유클리드 호제법(서로 나눔): 나머지로 최대공약수를 빠르게. 6/8→3/4. LCM=두 주기가 처음 겹치는 지점.
🎯 왜 이걸 쓰나: 할인율을 깔끔히 표기, 여러 정기혜택의 동시적용일을 미리 계산.
☕ Java
int gcd(int a,int b){ return b==0?a:gcd(b,a%b); }
long lcm = (long)a / gcd(a,b) * b;
🔍 왜 gcd(a,b) = gcd(b, a%b) ?
a·b의 공약수는 b와 "a를 b로 나눈 나머지"의 공약수와 똑같아요. 그래서 큰 수를 나머지로 줄여도 최대공약수는 그대로.
나머지가 0이 되면 그때 나눈 수가 답.
예) gcd(48,18)→gcd(18,12)→gcd(12,6)→gcd(6,0)=6.
1978
소수 찾기 — 쿠폰코드·주문번호 유효성 검사 (소수 판별)
💡 소수(素數)=더 못 쪼개는 "수의 원자". "나눠떨어지나"를 검사.
🎯 왜 이걸 쓰나: 위·변조 코드 걸러내기(체크섬류 검증)에 응용.
☕ Java
for(int i=2; i*i<=n; i++)
    if(n % i == 0) return false;   // 소수 아님
11050
이항 계수 — "방송 3종 세트" 번들 구성 가짓수 (조합)
💡 이항(二項)=두 항 + 계수=곱해진 수. n개 중 k개를 순서 없이 뽑는 수.
🎯 왜 이걸 쓰나: 기획전에 몇 가지 번들이 나오는지 미리 계산.
☕ Java
long r = 1;
for(int i=0; i<k; i++) r = r*(n-i)/(i+1);
🔍 왜 r = r*(n-i)/(i+1) ?
C(n,k) = (n·(n-1)···(n-k+1)) ÷ (1·2···k) 를 한 쌍씩 쌓는 거예요.
· 곱하는 (n-i) = 분자 한 개: i=0→n, i=1→n-1 …
· 나누는 (i+1) = 분모 한 개: i=0→1, i=1→2 …
매 단계 r은 항상 C(n, i+1)(=이항계수, 늘 정수)라 나눗셈이 딱 떨어짐.
예) C(5,2): r=1 → (×5÷1=5) → (×4÷2=10).
💡 n!을 직접 구하면 폭발(오버플로)하지만 이 방식은 r이 늘 작아 안전. 곱셈 먼저 하고 나눠야 정수가 안 잘림.
6064
카잉 달력 — 월정기 새벽배송 + 격주 정기구독 청구 겹침 (주기 겹침)
📜 카잉 달력? 가상 나라 카잉의 달력. 날짜를 <x:y>로 표기하고 x는 1~M, y는 1~N을 순환(매일 둘 다 +1, 넘으면 1로). 주기 M·N 두 톱니가 맞물려 특정 조합이 처음 나오는 날을 찾음(LCM 안, 중국인의 나머지 정리 계열).
💡 주기가 다른 두 사건이 처음 다시 겹치는 시각(최소공배수 계열).
🎯 왜 이걸 쓰나: 정기결제 충돌·중복청구 방지, 프로모션 겹침 예측.
☕ Java
for(long k=x; k<=lcm; k+=M)
    if((k-y) % N == 0){ ans=k; break; }
🔍 왜 k=x, k+=M, (k−y)%N==0 ?
첫째 달력이 x인 해 = x, x+M, x+2M … (M마다 첫째 달력이 다시 x). → 그래서 x부터 M씩 뛰며 후보를 봄.
그 후보가 둘째 달력도 y인지 = (k−y)가 N의 배수인지 (k−y)%N==0 (k와 y를 N으로 나눈 나머지가 같음).
둘 다 맞는 첫 k가 답. 두 주기가 함께 도는 LCM(M,N)까지 없으면 −1.
예) M=4,N=2,<3,1>: 후보 3,7,11… → (3−1)%2=0 → 답 3년째.

💰 8층. 가격·정산 엔진 (금융 기법 총집합)

8001
1회 매매 최대 수익 — 최저가 알림 / 최대 마진 (투포인터)
💡 투 포인터(두 지표)로 훑으며 최저가 대비 이익 갱신.
🎯 왜 이걸 쓰나: 매입-판매 마진 최대화, 최저가 알림.
☕ Java
best = Math.max(best, p - min);
min  = Math.min(min, p);
🔍 왜 best=max(best, p−min); min=min(min, p) ?
오늘 팔 때 최대 이익 = 오늘가 − 지금까지 최저가. 매일 최저가를 갱신하며 이익 최댓값을 유지.
사는 건 파는 날보다 먼저라, 이익부터 계산하고 min을 나중에 갱신.

💡 카데인: "이어갈지 / 새로 시작"을 매 값마다.
🎯 왜 이걸 쓰나: 연속 최고 매출 기간(성수기)을 O(n)에.
☕ Java

💡 슬라이딩 윈도우(창을 한 칸씩): 더하고 빼서 O(1).
🎯 왜 이걸 쓰나: 추세/이상탐지를 위한 이동평균을 빠르게.
☕ Java
sum += a[i];

🔍 왜 sum += a[i]; sum -= a[i-N] ?

🎯 왜 이걸 쓰나: 정산·회계 원장을 명령 순서대로 정확히 기록.

avg  = (avg*qty + price*n)/(qty+n);   // 매수: 평단
